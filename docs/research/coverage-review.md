# Independent coverage review — Sinjid system-level reverse engineering

Review date: 2026-10-27. Scope: read-only audit of the comprehensive report and retained catalogs against the full FFdec export. Only this findings document is authored by this review; original SWF, exports and game implementation remain unchanged.

## Assessment

The retained evidence is sufficient for a strong **static, system-level reconstruction of this Archive build**, not yet for an unqualified claim of complete behavioral validation. The outstanding work is a finite set of representative runtime questions below; it is not necessary to manually play every rank, every randomized damage result or every repeated stage.

The review used the full source tree for bounded checks, the source-linked world/UI reports, skills/combat and enemy-controller reports, equipment catalogs, verification script and comprehensive audit. Counts confirmed independently in this review: 684 exported text files; 24 gateway archetype names including five Rift bosses; 19 non-Rift archetypes plus five Rift archetypes. Original `.as` searches show SharedObject persistence and external promotional links, but no separate network gameplay/save backend in the game-specific code. Generic FUI component intervals are GUI implementation, not another gameplay system.

No unexplained independent gameplay subsystem was identified outside the reported categories. The catalog has major strengths: all nineteen learnable nodes, all class mutators, both damage callbacks, all living enemy controllers including inherited handlers, all forty encoded encounter definitions, all item definitions, shop frame-to-button mappings, hub room exits and save variants. Export parity alone would not establish those facts; the source-linked catalogs supply the semantic reconstruction.

A system-level completion statement can then say: **“All identified systems and all static content entries in this preserved build have been reconstructed; representative runtime semantics/flows were checked, with the listed compatibility or unreachable-content limits.”** It should not say every encounter was legitimately beaten or every RNG outcome reproduced unless that actually happened.

## Instrumentation constraints

A seeded probe may directly enter each authored encounter, but this proves scene/controller loading rather than an ordinary progression route or that the fight is beatable with an attainable build. Normal play already validates the first route; static guards plus a normal gate transition and representative high-level probes can support the system-level result without grinding35 fights.

For original callbacks/actions, log before and after state and actor/animation names. Avoid substituting a newly written implementation of the function as its own validation. A source-preserving wrapper is stronger than a parallel reimplementation. Preserve errors, NaN/undefined outputs and partial runs; do not normalize them away before the finding is recorded.

Instrumentation that grants stats, skills or stage counters should be visible in the scenario manifest. Exclude it from the claim that “no money/stats changed during normal play.” Those two statements can both be true when captures are separately labeled.

## Limits that need not block system-level completion

- Museum's protected SWF cannot currently be byte-compared to Archive; title/author/year/link provenance support the selected reference, but conclusions remain explicitly Archive-build-specific.
- WASP/WASP2/Blood Razor/Blacksmith do not have proven ordinary acquisition/entry paths. Keep them encoded/defined-only or unresolved; their speculative reachability is not a reason to claim more playable content.
- Duplicate WASP2 instance scheduling may remain a compatibility edge case if the extra encounter remains unproven reachable. If seeded probes expose it, document the result without adding it to normal stage counts.
- Every rank or every permutation of random AI/accuracy outcomes does not need execution once formulas, list weights, rank guards and representative runtime semantics are checked.
- Subjective balance/fun, full playtime, human accessibility study, every collision corner and release readiness of the new Godot game are separate future validation tasks. Do not use reference reverse engineering as a substitute for them.
